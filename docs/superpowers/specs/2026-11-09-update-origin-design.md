# 실행 경로 원본 파일 업데이트

사용자 요구: 업데이트 적용 시 실행한 경로의 지후니우스 파일도 최신으로 유지한다. 공유 폴더의 동일 파일을 여러 PC가 사용한다.

접근: 현재 PC별 검증/실행 구조에 원본 교체를 추가한다. 원본만 직접 실행하는 구조 변경은 업무 저장·재시작·복구 범위까지 바꾸므로 채택하지 않는다. 적용한 새 버전이 정상 시작한 뒤 원본을 교체하면 구 실행기에서 이번 버전으로 최초 업데이트할 때도 동작한다.

구현 판단: 공유 폴더 I/O는 제한 시간 10초의 별도 프로세스. 인접 잠금 파일로 여러 PC의 교체를 직렬화한다. 원본을 다시 읽어 버전/해시를 비교하고 최신 원본을 이전 버전으로 내리지 않는다. 알 수 없는 수정본은 보류. 검증된 임시 파일을 같은 폴더에서 원자적으로 교체하고 직전 원본 백업은 1개 유지한다.

실패 시 로컬 최신 버전은 계속 사용하고 업데이트 창에 원본 교체 보류 표시. 재시작 또는 기존 ‘다시 확인’으로 재시도하며 1분마다 공유 폴더를 반복 쓰지 않는다. 정상 저장 완료/미확인 입력 보호와 PC별 설정/업무 데이터는 유지한다. 다른 PC 실행 중인 버전은 강제 종료하지 않고 다음 시작부터 새 원본을 사용한다.

제약: Python 3.8+, 현재 공개 업데이트 프로토콜 1 유지. 실제 Windows SMB 파일 잠금/권한은 현장 확인 필요. 사용자 배포 요청 전에는 준비 브랜치와 전달 파일만 만든다. Drive 작업기록은 별도 요청 때만 갱신한다.

검토 보완: 다른 PC가 원본을 교체하는 순간 구 실행기가 이미 읽은 버전 상수와 다시 읽는 파일 바이트의 버전이 달라질 수 있다. 실행기는 실제 읽은 바이트의 버전을 사용한다. 이미 설치된 구 실행기에서 들어온 잘못 짝지어진 메타데이터도 새 자식이 자신의 검증된 파일과 버전으로 바로잡는다.

보류 기준: 실행 이후 다른 PC가 원본을 중간 버전으로 교체해 이 PC가 알고 있던 base/previous/current 해시 어느 것과도 일치하지 않으면 원본을 덮어쓰지 않고 완전 종료/재실행을 안내한다. 수동 수정 파일 보호를 우선한 선택이며, 단순히 두 PC가 같은 새 버전을 적용하는 경우는 정상 처리한다.
