# 지후니우스 공개 업데이트

현재 배포 버전은 `channels/stable.json`의 `version`이 기준입니다(README에 버전을 따로 적지 않습니다). 버전별 변경 내용은 `docs/releases/`와 업데이트 창의 안내에서 확인합니다.

## 처음 사용

1. 기존 지후니우스를 트레이 메뉴에서 **완전 종료**합니다.
2. `dist/지후니우스.pyw`를 기존 프로그램 폴더에 놓고 실행합니다. 기존 설정·데이터 파일은 그대로 둡니다.
3. 실행 파일의 위치는 이후에도 유지합니다. 바탕화면 바로가기를 자동으로 생성하지 않습니다.

기존 Windows용 Python 3.8 이상과 Tkinter를 그대로 사용합니다. EXE로 변환하지 않았습니다.
각 PC에 GitHub 로그인, Git, 별도 연결키를 등록할 필요가 없습니다.

## 업데이트 사용

- X 버튼을 누르면 **완전 종료 / 시스템 트레이로 보내기 / 취소** 선택창이 열립니다. 선택창의 X 또는 Esc는 취소입니다. 완전 종료는 기존 작업·저장·보조창 확인을 그대로 거칩니다.
- 바탕화면 바로가기 자동 생성과 수동 생성 버튼을 제거했습니다.
- 프로그램 시작 직후와 실행 중 1분마다 새 버전을 자동 확인합니다. 트레이에 숨겨 둔 상태에서도 확인하며, 다시 열 때도 마지막 확인으로부터 1분 이상 지났으면 확인합니다.
- 화면과 업무 기능은 먼저 실행하고, 네트워크 확인은 별도 작업에서 진행합니다.
- 새 버전이 있으면 상단에 **새 버전 있음**을 인수인계 알림과 같은 노란색으로 표시합니다. 재확인 중이거나 일시적으로 연결이 끊겨도 이미 확인한 알림은 유지합니다. 버튼에서 변경 내용·사용 안내를 읽고 **업데이트 후 다시 시작**을 누릅니다.
- 자동 확인은 버전 정보만 읽습니다. 다운로드·적용·재시작은 사용자가 업데이트 버튼을 눌렀을 때만 진행합니다. 확인 실패 시 다음 주기에 다시 확인하며 별도 알림창이나 로그 파일을 만들지 않습니다.
- 업데이트 확인에 실패하면 상단에 **확인 실패**를 표시합니다. 버튼을 누르면 현재 실행 버전, 마지막 확인 시각·성공 여부와 오류 안내를 볼 수 있습니다. 이미 새 버전을 찾았다면 일시적 확인 실패에도 노란 알림을 유지합니다.
- 파일 다운로드, 크기·SHA-256·문법 검사가 끝난 뒤 정상 종료하고 새 버전을 실행합니다.
- 열린 세척일보·돌출량표는 입력 중인 셀·공구대·메모까지 저장하고, 두 창의 저장 성공을 확인한 뒤 닫습니다. 저장 실패·응답 지연·취소 시 업데이트를 보류하며 강제 종료하지 않습니다. 저장 중에는 새 입력을 잠시 막습니다.
- 돌출량·세척일보 버튼은 첫 클릭에 열고 다시 클릭하면 해당 창의 기존 저장·종료 절차를 실행합니다. 저장 확인창에서 취소하면 열린 상태를 유지합니다. 빠른 연속 클릭으로 종료 요청을 중복 전송하지 않습니다.
- 두 창의 마지막 크기·위치는 각각 이 PC의 사용자 설정에 보관하며, 창을 다시 열거나 업데이트 후 실행해도 유지합니다. Windows의 다중 모니터 좌표를 그대로 보관하고, 모니터 구성이 바뀌어 창이 완전히 화면 밖에 있으면 Windows가 보이는 위치로 조정합니다. 최소화 상태로 다시 열지 않습니다.
- 위치 설정은 `%LOCALAPPDATA%\JihuniusSuite\window-state`의 프로그램별 JSON 파일입니다. 이동 중에는 메모리에 보관하고 750ms 동안 변경이 없을 때 파일 하나를 덮어쓰며, 종료 직전에도 저장합니다. 이 파일들만 삭제하면 다음 실행부터 기본 배치로 열립니다.
- 세척일보의 아직 전송하지 않은 부서 메모는 이 PC에 보관했다가 세척일보를 다시 열면 입력칸에 복원합니다. 자동 전송하지 않습니다.
- 2026.11.03.5 이하에서 업데이트할 때는 보조창을 직접 저장하고 닫아 주세요. 2026.11.03.6 이상에서는 업데이트 전에 자동 저장을 확인합니다.
- 세척완료·파일 작업·STL 검색 중이거나 파일 선택창이 열려 있으면 적용을 보류합니다. 입력 중인 프로그램 번호나 STL 주문은 보관 후 비워 주세요. 이후 버튼을 다시 누릅니다. 다운로드 중 업데이트 창을 닫으면 파일 준비만 마치고 재시작하지 않습니다.
- 연결 또는 다운로드 실패 시 기존 프로그램을 계속 사용합니다. 새 버전이 시작을 완료하지 못하면 이전 버전 선택을 복구하며, 업무를 자동으로 재실행하지 않습니다.
- 새 버전은 로컬의 별도 캐시에 보관합니다. 기존 원본 경로·PC별 설정·공유 데이터는 업데이트 대상으로 사용하지 않습니다. 장기 작업 로그를 수집하지 않습니다.
- 통합 지후니우스의 돌출량·세척일보·카드 수정 스크립트는 같은 배포 파일 안에 들어 있습니다. 따로 보관한 옛 독립 실행 파일은 이 통합본의 업데이트 대상이 아닙니다.

## 관리 및 후속 수정

### 공유폴더의 같은 실행 파일을 여러 PC에서 사용할 때

- 공유폴더의 원본 `.pyw`는 실행 진입점입니다. 업데이트 파일·현재 버전·복구 상태·실행 잠금은 각 PC/Windows 사용자 계정의 `%LOCALAPPDATA%`에 저장하며, 업데이트가 공유 원본을 덮어쓰지 않습니다. 각 PC에서 업데이트 적용이 필요합니다.
- 알림 대상·소리·음량, 창 위치, STL 설정 및 MES 버튼 설정도 PC별입니다. 실행 파일 이름과 경로는 일정하게 유지하세요.
- 날짜 폴더 옆 **경로설정**에서 `★ 2026` 같은 연도 폴더가 들어 있는 NC프로그램 기본 폴더를 선택하거나 입력한 뒤 저장합니다. 설정은 `%LOCALAPPDATA%\Jihunius\program_paths.json`에 보관합니다. 연도·월·날짜 구조와 날짜 표기 처리, 리스트만 만들기 동작은 유지합니다. 설정 저장 시 공유폴더 접속을 요구하지 않으며, 실제 작업 때 기존 방식으로 접근 여부를 확인합니다.
- STL 폴더는 `%LOCALAPPDATA%\DentalFileFinder\settings.json`에 보관합니다. 폴더 선택은 즉시, 직접 입력은 검색 시작이나 정상 종료 때 저장하며, 배포본의 기본 경로가 바뀌어도 사용자가 저장한 폴더를 우선합니다. 공유 실행 파일을 사용하는 PC끼리 이 설정을 덮어쓰지 않습니다.
- 세척일보·돌출량·인수인계의 업무 데이터는 공유합니다. 저장 잠금과 수정 충돌 검사를 유지하며, 세척일보의 데이터 폴더는 세 PC에서 같은 곳을 선택해야 합니다.
- 돌출량표는 공유폴더 연결 오류를 파일 없음으로 간주해 초기화하지 않도록 보강했습니다. 실제 새 파일이고 폴더에 접근 가능한 경우에만 처음 표를 만듭니다.
- 세척완료 MES/POP 자동화에는 PC 사이의 동시 실행 잠금이 없습니다. 같은 대상 작업은 한 PC에서 진행하세요. 이번 배포는 세척완료 로직을 바꾸지 않았습니다.
- 회사 PC에서 노란 업데이트 알림이 보이지 않은 정확한 원인은 아직 확인되지 않았습니다. 공개 배포와 시작·주기 확인, 색상은 테스트 환경에서 정상이며, 새 표시로 각 PC의 버전과 실패 여부를 확인할 수 있습니다.

### 소스 구조와 빌드

배포 파일은 여전히 **한 개의 `.pyw`** 입니다(업데이트가 파일 하나를 내려받는 방식). 다만 `apps/jihunius/app.pyw`는 이제 **직접 고치지 않는 빌드 결과물**입니다. 아래 원본을 수정한 뒤 빌드합니다.

| 원본 | 내용 |
|---|---|
| `src/host/jihunius_main.py` | 메인 화면·파일 가져오기·드라이브 정리·설비 모니터·인수인계 (`NAME = ...  # build:` 줄은 빌드 때 채워짐) |
| `src/host/stl_finder.py` | STL 찾기 |
| `src/host/wash_mes.py`, `src/host/wash_pop.py` | MES/POP 세척완료 자동화 |
| `src/host/card_modifier_10_30.py` | 카드에 복사되는 수정10.30 스크립트 |
| `src/host/windows_tray.py` | 시스템 트레이 |
| `src/*.py` | 돌출량·세척일보·특수 돌출량·소재 사용량 조사·오류 기록·업데이트 |
| `assets/` | 앱 아이콘, 알림 스위치 이미지, 알림음 |

```sh
python tools/build_app.py            # 원본 → apps/jihunius/app.pyw
python tools/build_app.py --check    # app.pyw가 원본의 빌드와 같은지 확인
python -m unittest discover -s tests -p 'test_*.py'
```

`tests/test_build_app.py`가 커밋된 `app.pyw`와 원본 빌드가 바이트 단위로 같은지 검사합니다. 같은 원본이면 어느 PC에서 빌드해도 같은 파일이 나옵니다.

### 배포

변경 내용을 UTF-8 텍스트로 작성한 뒤 새 버전을 준비합니다. 버전 번호는 `src/host/jihunius_main.py`에도 자동 반영됩니다.

```sh
python tools/prepare_release.py 2026.11.09.9 --notes docs/changes.txt
python -m unittest discover -s tests -p 'test_*.py'
```

새 버전에서 기존 기능과 실제 Windows 동작을 검증한 뒤 `src/`, `apps/`, `dist/`, 새 `releases/` 파일, `channels/stable.json`을 **한 커밋**으로 올립니다. 이미 배포한 버전 파일은 덮어쓰지 않고 새 번호를 부여합니다. `.gitattributes`는 파일 바이트가 체크아웃 환경에 따라 바뀌지 않도록 유지합니다.

앱이 읽는 정식 배포 기준은 `main` 브랜치의 `channels/stable.json`입니다. 다른 브랜치에 올린 수정이나 소스 수정만으로는 배포되지 않습니다. GitHub Releases 화면에 설명만 등록해도 자동 적용되지 않습니다.

### 자동 테스트

`main`과 작업 브랜치에 올리면 GitHub Actions(`.github/workflows/tests.yml`)가 Linux(Xvfb)에서 전체 테스트를 실행하고, Windows에서도 참고용으로 실행합니다. 화면 배치 검사 일부는 글꼴에 따라 결과가 달라질 수 있어 Windows 결과는 참고용입니다.

## 검증 범위

시작 직후·주기적 자동 확인, 연결 실패 후 재시도, 노란색 알림 유지, 중복 요청 방지, 종료 시 예약 해제를 자동 테스트로 확인했습니다. 실제 Tk 화면에서도 버튼을 누르지 않은 첫 확인과 트레이 상태 재확인, 기본·150% 배율에서 노란색 버튼 배치를 확인했습니다.

임시 폴더·실제 Python 자식 프로세스에서 버전 확인, 손상 파일 거부, 명시적 적용, 재시작, 시작 실패 복구, 기존 데이터 보존, 중복 실행 억제를 검사했습니다. 실제 Tk 화면에서 기본 배율 및 150% 배율의 배치도 확인했습니다.

종료 선택창의 취소·X·Esc, 중복 열기, 트레이 이동·복원, 저장 중 종료 보류, 보조창 종료 대기를 기본 배율 및 150% 배율의 실제 Tk 화면에서 확인했습니다. 바로가기 생성 코드와 버튼 제거도 확인했습니다.

업데이트 전 저장 성공·실패·취소, 잘못된 저장 응답 거부, 저장 중 새 작업 차단, 다운로드 취소 후 재시작 방지를 검사했습니다. 실제 Tk 창과 임시 공유폴더에서 돌출량 메모·제품명, 세척일보 편집 중 업체명·공구대 저장과 미전송 메모 보관을 확인했습니다.

각 보조창의 크기·위치 독립 저장, 이동 직후 최소화·종료, 잘못된 설정 및 쓰기 실패 처리를 자동 검사했습니다. 실제 Tk 창을 서로 다른 크기·위치로 종료한 뒤 별도 프로세스로 다시 열어 복원되는 것을 확인했습니다. Windows 네이티브 위치 복원과 다중 모니터는 현장 검증 대상입니다.

세척일보의 최초 idle 콜백이 Tk의 MapFrame 내부에서 실행되어 실제 Windows 최상위 창 생성보다 먼저 위치를 복원하는 순서 오류를 확인했습니다. 루트 창의 최초 Map 이후에만 복원하며, 이미 표시된 돌출량과 재매핑·초기 종료도 검사합니다. `test_window_mapping.py`는 실제 Tk 화면이 필요하며, 화면 없는 환경에서는 해당 3개 검사가 생략됩니다.

동일 원본 파일을 사용하는 세 개의 독립 로컬 캐시에서 업데이트가 서로 덮어쓰이지 않는지 검사했습니다. 돌출량표의 네트워크 이름 오류를 주입해 기존 데이터가 유지되는지, 최초 생성과 같은 칸 수정 충돌이 정상인지 확인했습니다. 실제 회사 SMB와 여러 PC의 POP 동시 저장은 실행하지 않았습니다.

실제 Windows의 트레이·한글 IME·회사 공유폴더와 MES/POP 연동은 현장 확인이 필요합니다. 이번 버전에서 세척완료 MES/POP 소스는 변경하지 않았습니다.


## 특수 돌출량

- 돌출량 오른쪽 **특수 돌출량** 버튼으로 열고, 같은 버튼을 다시 누르면 저장 후 닫습니다.
- 타입명 / 수정 치수 / 비고의 세 열입니다. 셀을 한 번 클릭해 편집하며 Enter 또는 다른 칸 선택으로 반영합니다. Shift+Enter는 셀 안의 줄바꿈입니다. 하단 특이사항도 항상 수정 가능합니다.
- **+ 줄 추가**로 새 줄을 만들고, 필요 없는 줄에서 **우클릭 → 줄 삭제**를 누르면 별도 확인 없이 삭제합니다. 검색한 상태에서도 클릭한 줄의 식별자로 삭제합니다. 다른 PC가 동시에 해당 줄을 수정한 경우에만 충돌을 확인합니다.
- 인수인계 공유폴더 안의 `특수_돌출량.json` 하나를 PC끼리 공유합니다. 행 추가·수정·삭제와 특이사항이 반영되며, 정상 연결 시 열린 창은 기존 2.5초 주기로 동기화합니다. 데이터 파일이 존재하면 내장 표를 다시 덮어쓰지 않습니다.
- 삭제한 줄이 오래된 요청으로 되살아나지 않도록 삭제된 식별자만 함께 보관합니다. 삭제된 본문이나 작업 이력은 누적하지 않습니다. 수정과 삭제가 겹쳤다면 수정한 내용을 새 줄로 복원할지 선택할 수 있습니다.
- 창 위치·크기와 미저장 임시 복구 내용은 PC별입니다. 접속 오류·동시 수정·저장 실패 시 기존 내용을 조용히 초기화하지 않습니다. 표와 메모는 원자적 저장 전에 4MB 제한을 검사합니다.
- 이전 테스트 파일은 자동 업데이트 대상이 아닙니다. 테스트 파일을 완전 종료한 뒤 기존 정식 지후니우스에서 업데이트하거나 `dist/지후니우스.pyw`를 기존 정식 실행 파일 위치에 놓고 사용하세요.

이번 배포에는 돌출량의 응답 제한·미저장 복구, 인수인계 연결 오류 처리, 드라이브 읽기 비동기화도 포함됩니다. 읽기 작업은 한 번에 하나만 진행하고 드라이브 작업 전 기존 검증을 유지합니다. OS가 드라이브 읽기에서 응답하지 않으면 백그라운드 읽기가 점유된 채 남을 수 있으며 화면은 계속 반응합니다. 실제 Windows·회사 공유폴더·USB 환경은 별도 현장 확인이 필요합니다.
